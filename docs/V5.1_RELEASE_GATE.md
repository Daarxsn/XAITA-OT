# XAITA-OT V5.1 Release Gate

This checklist records the V5.1 baseline-hardening status for the OT/ICS security analytics product.

## Product safety and trust boundaries

- [x] Canonical pipeline remains Observation → Detection → Episode → Context → Attribution → Explanation → Risk → CTI.
- [x] Detection Confidence (DC) remains distinct from Attribution Confidence (AC).
- [x] Evidence identifiers and provenance remain part of the analytical contract.
- [x] Attribution is analyst-support-only; the product does not issue autonomous OT control actions.
- [x] Uncertainty is presented as uncertainty and is not represented as calibrated probability without validation.

## Deployment and API hardening

- [x] Container copies `web/` into the runtime image.
- [x] Dashboard resolution supports an explicit `XAITA_OT_ROOT` deployment root.
- [x] Dashboard resolution supports the Render/container working-directory layout.
- [x] `/ready` reports whether the dashboard asset is available.
- [x] `/` returns HTTP 503 with a clear diagnostic when the asset is genuinely absent.
- [x] Regression tests cover configured-root resolution, working-directory fallback, and readiness reporting.
- [ ] External Render deployment must be redeployed from the latest `main` commit.
- [ ] Live checks must confirm `/health`, `/ready`, and `/` after redeployment.

## Quality and release evidence

- [x] V5.1 capability contract exists.
- [x] Package metadata is aligned to version `0.5.1`.
- [x] CI includes supported Python-version test jobs.
- [ ] Latest commit CI result must be recorded before declaring the gate closed.
- [ ] Clean-install and live deployment verification must be recorded before moving to V5.2.

## Release rule

V5.2 work must not begin until the unchecked deployment and verification items above are completed. No benchmark, production-readiness, or enterprise-compliance claim is made by this checklist alone; those claims require separate evidence and customer-specific validation.
