# XAITA-OT V4.2.3 — API Contract

## Purpose

This document defines the externally consumable API contract for XAITA-OT V4.2. It is a compatibility and implementation baseline; it does not claim production OT deployment certification.

## Runtime endpoints

| Method | Route | Purpose | Authentication |
|---|---|---|---|
| GET | `/health` | Liveness and service version | Public |
| GET | `/ready` | Readiness and deployment capability summary | Public |
| GET | `/` | Dashboard asset | Public |
| GET | `/v2/datasets` | Dataset configuration/status | API key when configured |
| POST | `/v2/experiment` | Execute a configured dataset experiment | API key when configured |
| POST | `/v1/analyze` | Analyze a bounded list of detection events | API key when configured |

## Authentication

When `XAITA_API_KEY` is unset, protected routes operate without an API key for local development. When it is set:

- Missing key: HTTP `401` with `{"detail":"API key required"}`
- Incorrect key: HTTP `403` with `{"detail":"Invalid API key"}`
- Header: `X-XAITA-API-Key`

## `/v1/analyze`

### Request

A non-empty JSON array of event objects:

- `event_id`: string, 1–128 characters
- `timestamp`: ISO-8601 datetime
- `asset`, `protocol`, `source`, `destination`, `label`: non-empty strings with bounded lengths
- `detection_confidence`: number from 0 to 1
- `features`: object of numeric feature values

Unknown fields are rejected. The request is rejected with HTTP `400` when empty and HTTP `413` when it exceeds `XAITA_MAX_EVENTS` (default 5000).

### Response

```json
{
  "incidents": []
}
```

The `incidents` value is the engine-generated incident result and must be treated as a versioned output contract before external integrations are enabled.

## `/ready`

```json
{
  "status": "ready",
  "dashboard": true,
  "max_events": 5000
}
```

`dashboard` indicates whether the configured dashboard asset exists. Readiness does not imply that external datasets are configured.

## Error policy

- `400`: malformed or semantically invalid request
- `401`: required API key missing
- `403`: API key invalid
- `409`: requested dataset is not configured or unavailable
- `413`: request exceeds configured event limit
- `422`: FastAPI/Pydantic validation failure
- `503`: dashboard asset unavailable

## Compatibility rules

1. Existing V1–V3 routes and response behavior must not be changed without regression tests.
2. New fields must be additive unless a major API version is introduced.
3. Client integrations must not depend on undocumented fields.
4. API responses must not expose secrets or local filesystem credentials.
5. Any change to the incident output requires fixture-based contract tests.

## Acceptance criteria

- OpenAPI documentation is reachable at `/docs`.
- Invalid and unknown request fields are rejected.
- Authentication behavior is covered by tests.
- Event limits are covered by tests.
- Health/readiness behavior is covered by tests.
- A valid analysis request returns an `incidents` field.
- Python 3.11 and 3.12 CI remain green.
